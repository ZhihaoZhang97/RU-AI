# Contributing to RU-AI

Thanks for your interest in RU-AI, the official repository for our WWW'25 Resources Track paper
[*RU-AI: A Large Multimodal Dataset for Machine-Generated Content Detection*](https://arxiv.org/abs/2406.04906).

This is a small research repository maintained by the paper's authors in their spare time. To keep it
reviewable, please read this before opening a pull request.

## Open an issue first

For anything beyond a one-line typo fix, **please open an issue before writing code**. This includes new
scripts, changes to the download or inference pipeline, dependency bumps, and any new documentation file.
We would much rather discuss a change than close a PR you already spent time on.

## What we welcome

- Bug reports and fixes for `download_all.py`, `download_flickr.py`, and the inference scripts
- Reproducibility problems: environment and version conflicts, broken dataset links, checksum mismatches
- Corrections to factual errors in the README (dataset statistics, citations, references)
- Clarifications to the setup instructions, based on an actual failure you hit

## What we do not accept

**Unsolicited translated documentation.** We will close any PR that adds a `README.<locale>.md` or
equivalent without prior discussion in an issue. We appreciate the intent, but no maintainer here can
review or maintain a translation, and a translation nobody maintains drifts out of sync with the English
README until it actively misleads readers. If you want to maintain one long-term, open an issue and say
so — we are happy to talk about it.

**Machine-generated pull requests.** PRs produced by an automated agent that forks the repository and
opens a change with no human in the loop will be closed, and accounts submitting them at scale will be
reported to GitHub as spam.

**Drive-by cosmetic changes.** Reformatting, whitespace normalization, badge shuffling, adding linters or
CI, renaming things — unless we asked for it in an issue.

## Disclosing AI assistance

Using an LLM to help write code or prose is fine, and you do not need to be cagey about it. What we
require is that **a human has read and verified every line before the PR is opened**, and that you say so
in the description. Something like "drafted with an LLM, tested locally on CUDA 11.8" is all we need.

A PR whose description amounts to "generated by `<model>`", with no evidence that anyone checked the
output, will be closed without further discussion.

## Dataset questions

Questions about dataset contents, licensing, or access belong in an issue rather than a PR. The dataset
itself lives on [Zenodo](https://zenodo.org/records/11406538) and
[HuggingFace](https://huggingface.co/datasets/zzha6204/RU-AI-origin) — please report data problems here so
that other users can find the discussion.

## Citation

If you use the dataset or find our research useful, please cite the paper — see the Citation section of
the [README](README.md).
